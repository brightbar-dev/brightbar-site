Privacy Policy — Cookie DevTools

Last updated: 2026-09-15

Data Collection

Cookie DevTools does not collect, transmit, or share any user data. It has no analytics, no tracking and no ads, and it makes no network requests. Everything it stores stays on your device.

Permissions Explained

  • cookies: Required to read, create, edit and delete browser cookies — the core functionality.
  • host_permissions (<all_urls>): An extension can read and write a site's cookies only if it has access to that site, and you might be working on any site. Chrome describes this access at install as "Read and change all your data on all websites". Cookie DevTools uses it only for cookies and to see which site the active tab (or the page DevTools is inspecting) is on. It never reads page content and never injects scripts into pages.
  • activeTab: Lets the popup show the site you are on when you open it.
  • storage: Saves your settings, cookie profiles, Protect/Block rules and, only if you turn Record on, the change log — all locally on your device.
  • sidePanel: Shows the same cookie tools in Chrome's side panel, which stays open and follows your tabs.

The extension does not request the tabs permission. Its DevTools panel requires no additional permission.

Data Storage

  • Profiles (named cookie snapshots) and Protect/Block rules are stored locally using chrome.storage.local.
  • Change monitor: the live view is kept in memory only. The saved change log — including cookie names, values, domains and the cause of each change — is written only while you have Record switched on, for the scope you choose, and you can clear it at any time.
  • Import and export: files and text you import are read locally in the extension. Exports go to your clipboard or to a file you download. Nothing is uploaded.
  • No data is sent to any server or third party.

Changes to This Policy

If this privacy policy changes, the updated policy will be posted here and the "last updated" date will be revised.
