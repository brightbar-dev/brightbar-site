Privacy Policy — Browser API Client

Last updated: 2026-09-15

Data Collection

Browser API Client does not collect, transmit, or share any personal data. It has no account, no sign-in, no analytics and no telemetry, and it sends nothing to Brightbar.

Permissions Explained

  • host_permissions (<all_urls>): Required to send HTTP requests to any API endpoint you choose and to read the full response. Requests are sent only when you press Send or run a collection. Chrome describes this access as "Read and change all your data on all websites"; the extension injects no scripts into pages and does not read or change the websites you browse.
  • storage: Saves your work on your device: open request tabs (drafts), request history, environments, collections, OAuth 2.0 tokens and settings.
  • identity: Used only for OAuth 2.0 authorization-code sign-in. When you click "Get new access token", the browser opens the sign-in page of the provider you configured and returns the authorization code to the extension. The extension never reads your browser or Google account profile.
  • webRequest: Observes the network events of the extension's own requests, inside its own app tab, to show you details the browser otherwise hides: the redirect chain, Set-Cookie response headers, and the real cause of a network failure (for example DNS, TLS or a refused connection). It observes no other tab, and it blocks or modifies nothing.

How API Requests Work

Requests are sent directly from the extension's app page in your browser to the URL you entered — no proxy, no intermediary server. Request and response data stays in your browser.

  • Cookies: requests never carry your browser's cookies unless you turn on "Send this site's cookies" for that specific request.
  • OAuth 2.0: tokens are requested from the token endpoint you configure, stored locally in your browser, and never included in exports, backups or shared collections.
  • First run: the workspace opens with a sample request to httpbin.org, a public echo service. It is sent only if you press Send.

What the extension does NOT do

  • Does not collect analytics or usage data
  • Does not use tracking pixels or third-party scripts
  • Does not proxy requests through any server
  • Does not access your browsing history
  • Does not read or modify the content of the pages you browse
  • Does not require an account or sync anything to a cloud

Data Storage

Everything — drafts, history, environments, collections, tokens and settings — is stored locally on your device using the browser's storage (including IndexedDB for large responses and attached files). Backups are JSON files that you export and import yourself from Settings. You can delete any of this data at any time. No data is stored on external servers.

Changes to This Policy

If this privacy policy changes, the updated policy will be posted here and the "last updated" date will be revised.

Contact

If you have questions about this privacy policy, please file an issue on the extension's support page.
